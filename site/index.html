Query fan-out

robots.txt が約束していないこと

robots.txt は RFC 9309 として標準化されています。読むべきは、そこに書いていないことです。

  • アクセス認可ではない。RFC 9309 は "These rules are not a form of access authorization." と書きます。守るかどうかは相手次第です
  • 用途を区別できない。学習か検索かエージェントか、という概念は規格にありません。ベンダーが User-Agent（以下 UA）名を分けて実現しているだけです
  • 最長一致。複数の規則が当たったら、オクテット数が最も多い規則が使われます
  • パスは大小を区別し、UA トークンは区別しない。パスの照合は case sensitive（SHOULD）、UA の照合は case-insensitive（MUST）
  • 4xx と 5xx で結果が正反対になる。robots.txt が 4xx を返したときは、クローラーは「どのリソースにもアクセスしてよい」と解釈します。5xx を返したときは「全面禁止」とみなします
  • キャッシュは 24 時間まで。パーサーは最低 500 KiB を読む

秘密の URL を robots.txt で隠すのは筋が悪いという話が、ここに繋がります。止めたいものは認証で止めてください。
