# 本文の書き方（_fragments 共通）

`_fragments/*.html` の日本語はこのルールに従う。`build.py` が一部を機械チェックする（`python3 site/build.py` の警告）。

## 1. 比喩・造語は使わない。使うなら初出で一文定義する

読者に推測させる語を裸で出さない。定義を置くか、具体物に置き換える。

| 使わない | 置き換え先 |
|---|---|
| 入場 | 入場条件（第1章で「インデックスに載り、スニペットを出せる状態」と定義。以降は「入場条件」） |
| スイッチ | AI 面の設定（第8章で「メタタグ / robots.txt のトークン / Search Console の設定の三種類」と定義） |
| 塊 | 段落。UI の読み進み単位は「節」と呼ぶ（章 → 節 → 想起カード） |
| 出典の厚さ | 回答文に占める分量と位置 |
| 接地 | 根拠として参照すること（grounding）。第4章で定義してから使う |
| 止める（反論の意味） | 反論する。第9章で「一次情報をぶつけて反論すること」と定義してから使う |
| 青リンク / 本戦 | 検索結果一覧のリンク / 勝負どころ |
| ハブを生やす | 中身の薄いまとめページを量産する |

## 2. 番号や指示語で参照せず、名前で呼ぶ

- 不可: 「3, 4, 5 以外は」「1 が落ちているのに 2 を」「二つは同じ現象を」
- 可: 「キーワード詰め込み・出典の明記・引用文の追加の 3 つ以外は」「論文と Google 公式は」

読者に前の行との照合作業をさせない。リスト項目を指すときもラベル名を書く。

## 3. 一文一主張。動詞句＋読点＋助詞の構文を使わない

- 不可: 「学習だけ拒否して検索は許可する、が公式に想定されています」
- 可: 「学習用ボットだけを拒否し、検索用ボットは許可するという設定は、公式に想定されています」

引用したい語句は鍵括弧で括るか、「〜という設定は」と体言化して主語を明示する。「〜まで。」で切る省略形も使わない（「〜というところまでです」と書く）。

## 4. 主語を省かない。指示と事実を書き分ける

- 読者への指示 → 「〜してください」
- 事実の記述 → 「〜になります」「〜です」

主語なしの意志形（「点検します」「取りに行きません」「外します」）は、指示か事実か判別できないので使わない。二重否定も使わない（「事実誤認が見つかる書き方をしていない」→「事実の誤りが残っていない」）。

## 5. 英略語・原語は初出で和訳を添え、以降は表記を固定する

| 概念 | 固定表記 | 初出時 |
|---|---|---|
| 論文の実験エンジン | 内部 GE | 「論文が自作した生成エンジン（以下、内部 GE）」 |
| Search Console の AI 設定 | 生成 AI control | 「Search Console の Search generative AI control（以下、生成 AI control）」 |
| Google の AI 回答面 | AI Overviews | 「AI Overviews（AI 概要）」 |
| 位置補正の指標 | 位置補正単語数 | 「位置補正単語数（Position-Adjusted Word Count）」 |
| クエリの展開 | query fan-out | 「query fan-out（1 つの質問を複数の下位クエリに分けて検索すること）」。カナ表記「ファンアウト」は使わない |
| User-Agent | UA | 「User-Agent（以下 UA）」 |
| 論文のモデル | 実験条件を述べるときだけ `gpt-3.5-turbo`、一般記述は GPT-3.5 | — |

初出で和訳が必要な略語: SERP（検索結果ページ）、C-SEO（competitive SEO、競合が同じ手法を採る条件下の SEO）、WAF（Web Application Firewall）、UGC（ユーザー投稿コンテンツ）、MAU（月間アクティブユーザー数。「月間 25 億 MAU」は重複なので「月間アクティブユーザー 25 億」）。

## 6. カタカナ末尾の長音符は付ける

ユーザー、サーバー、クローラー、パーサー、ブラウザー。

## 7. 講義メモではなく、読み物として書く

1 文だけの段落を積み上げない。読者が「なぜそうなるのか」を追える形にする。

- **段落に束ねる。** 関連する 2〜5 文を 1 段落にまとめる。段落の 1 文目でその段落の主張を言い、残りで支える。
- **因果をことばでつなぐ。** 「というのも」「だから」「その結果」「一方で」「ただし」を使い、文と文の関係を読者に推測させない。
- **抽象的な命題には例を 1 つ添える。** 「たとえば〜」で、教材の中ですでに述べた事実か、明らかに仮の例（自社サイト、ある製品ページ）を使う。**新しい事実・数字・製品の挙動を作らない。**
- **節の入口と出口を作る。** 節の最初の 1 文でこの節で何を見るのかを示し、最後の 1 文で次に何が問題になるのかへつなぐ。
- **箇条書きは並列の列挙にだけ使う。** 説明や理由づけを箇条書きに逃がさず、地の文で書く。表と `<div class="flow">` は現状のまま残す。

書き換えても、一次情報の事実・数字・実験条件・出典・カードの答えの主張は変えない。

## 8. 触らないもの

- 一次情報からの引用文（英語原文、数値、論文タイトル、著者名）
- 出典 `<details class="source">` の中身
- `<card>` の答えの事実関係。言い回しは直してよいが、主張・数値・条件は変えない
- HTML の構造、クラス名、`data-term` 属性値
