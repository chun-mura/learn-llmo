三つの役割

主要ベンダーはボットをだいたい三種に分けます。設定は独立です。

役割名前の例止めると
学習GPTBot, ClaudeBot, Google-Extended将来の学習（と、製品によってはアプリ側の接地）から外れる
検索インデックスOAI-SearchBot, Claude-SearchBot, PerplexityBot, Googlebotその製品の出典候補から外れる
ユーザー起動ChatGPT-User, Claude-User, Perplexity-User今この質問のためのライブ取得

学習だけ拒否して検索は許可する、が公式に想定されています。

ボットの三つの役割を挙げ、それぞれを止めると何が起きるか言ってください。

学習（止めると将来の学習や製品によってはアプリ側の接地から外れる）、検索インデックス（止めるとその製品の出典候補から外れる）、ユーザー起動（止めると今この質問のためのライブ取得が止まる）。三つの設定は独立で、学習だけ拒否して検索は許可できる。

robots.txt が約束していないこと

robots.txt は RFC 9309 として標準化されています。読むべきは、そこに書いていないことです。

  • アクセス認可ではない。RFC 9309 は "These rules are not a form of access authorization." と書きます。守るかどうかは相手次第です
  • 用途を区別できない。学習か検索かエージェントか、という概念は規格にありません。ベンダーが UA 名を分けて実現しているだけです
  • 最長一致。複数の規則が当たったら、オクテット数が最も多い規則が使われます
  • パスは大小を区別し、UA トークンは区別しない。パスの照合は case sensitive（SHOULD）、UA の照合は case-insensitive（MUST）
  • 4xx と 5xx は逆に働く。robots.txt が 4xx なら「どのリソースにもアクセスしてよい」、5xx なら「全面禁止とみなす」
  • キャッシュは 24 時間まで。パーサは最低 500 KiB を読む

秘密の URL を robots.txt で隠すのは筋が悪い、という話がここに繋がります。止めたいものは認証で止めます。

robots.txt が 5xx を返しているとき、規格上クローラはどう振る舞いますか。4xx のときは。

5xx（到達不能）なら "complete disallow" とみなす＝全面禁止。4xx（利用不可）なら "MAY access any resources on the server"＝どのリソースにもアクセスしてよい。逆に働くので、サーバ障害中は正規のクローラも止まる。

 RFC 9309 は robots.txt の規則を何ではないと明記していますか。

アクセス認可ではない（"These rules are not a form of access authorization."）。守るかどうかは相手次第であり、規格には学習・検索・エージェントという用途の区別もない。用途はベンダーが UA を分けて実現しているだけ。

robots.txt の外側で動いているもの

用途を書けない、という RFC の穴を、二方向から埋めようとしています。どちらもまだ標準ではありません。

IETFaipref WG。Content-Usage を HTTP ヘッダと robots.txt の両方に付け、取得と利用を二段に分ける。Internet-Draft であり RFC ではない
CloudflareSearch / Agent / Training の三分類。2026-09-15 から、新規ドメインの広告掲載ページで Training と Agent を既定でブロック。Search は許可のまま

Cloudflare は Content-Signal: というディレクティブも出しています。Content-Signal: search=yes,ai-train=no のように書きます。

実務の含意は一つです。自分が robots.txt に何も書いていなくても、CDN 側の既定でブロックが入ることがあります。「許可したつもり」を確かめる先が増えました。

IETF aipref の Content-Usage は、いま何の段階ですか。robots.txt と何が違いますか。

Internet-Draft（aipref WG、Proposed Standard 志向）で、RFC ではない。robots.txt が取得の可否を書くのに対し、Content-Usage は利用の意向を書く。取得と利用を二段に分ける設計で、HTTP ヘッダと robots.txt の両方に付ける。

 Cloudflare のボット三分類と、2026-09-15 から何が変わるかを言ってください。

Search（収集して後で答えるためのインデックス）／ Agent（人の代理でいま行動する）／ Training（学習用の収集）。2026-09-15 から、新規に Cloudflare へ載せるドメインでは、広告を出しているページで Training と Agent が既定でブロックされる。Search は許可のまま。
